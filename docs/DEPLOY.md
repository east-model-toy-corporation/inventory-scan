# 部署條碼盤點

1. 建立 Google 試算表，開啟「擴充功能」→「Apps Script」。
2. 將 `gas/Code.gs` 貼入 Apps Script 的程式碼檔。在「專案設定」勾選「在編輯器中顯示 appsscript.json 資訊清單檔案」，再貼入 `gas/appsscript.json`。
3. 依下方「設定 API 金鑰」選擇一種方式。使用雲端盤點的裝置都需要填寫同一組金鑰。
4. 在編輯器選擇並執行 `setup()`，依提示授權。回到試算表確認已建立「主檔」、「場次」、「刷讀明細」和「彙總」。手動貼上主檔前，將條碼欄設為「純文字」，以保留前導零。門市欄留空表示所有門市適用。
5. 點選「部署」→「新增部署作業」，類型選「網頁應用程式」。執行身分選「我」，存取權選「所有人」。部署後複製以 `/exec` 結尾的網址。
6. 在 GitHub 儲存庫開啟「Settings」→「Pages」，選擇「Deploy from a branch」，選擇放置 `index.html` 的分支與目錄。前端以相對路徑載入資源，可放在 GitHub Pages 的儲存庫子路徑。
7. 開啟 GitHub Pages 網址，在「設定」填入金鑰後按「測試連線」。GitHub Pages 版使用 `js/config.js` 中的預設 API 網址。若使用自己的部署，請填入該部署的 `/exec` 網址。清空欄位會恢復使用預設網址。相機需要 HTTPS，iPhone 請使用 Safari。

更新 Apps Script 時，選擇「部署」→「管理部署作業」→「編輯」→「新版本」，然後部署，以沿用原有的 `/exec` 網址。

「刷讀明細」欄位依序為 時間｜場次｜門市｜盤點人｜區域｜裝置｜條碼｜品名｜數量｜id｜更新時間｜狀態。區域為選填，未填時明細保留空白，依區域彙總則顯示「未填區域」。舊版明細會在執行 `setup()` 或收到第一個通過驗證的 API 請求時自動更新，保留既有盤點紀錄。

盤點人員選好門市並按「開始盤點」後，系統會加入該門市進行中的場次，或以台北日期建立新場次。場次可持續跨日，直到有人在「設定」按「結束盤點」並輸入管理密碼。結束前會先嘗試上傳待同步明細。離線時待上傳明細會留在本機，恢復連線後可重新輸入管理密碼。未上傳明細仍可匯出本機備份。結束後可從「彙總」查看及匯出上一場。

建立有主檔的場次，或加入尚無主檔的有主檔場次時，可先匯入 POS 的 Excel／CSV，再按「開始盤點」。設定雲端後，主檔會自動上傳到該場次，加入者會自動載入。上傳失敗時會顯示「主檔待上傳」並自動重試。可在「彙總」重新載入主檔，或經確認後覆蓋場次主檔。匯入時若同一條碼出現多次，以最後一列為準。

舊版「主檔」分頁會自動在最左側加入「場次」欄。場次欄留空的資料仍可在場次沒有專屬主檔時依門市使用。

## 設定 API 金鑰

主管可將以下格式的設定連結透過 LINE 私訊等私人管道傳給同仁。請勿將金鑰或含金鑰的設定連結提交到 Git。

- 使用目前的 API 網址：`https://<帳號>.github.io/inventory-scan/#key=<API金鑰>`
- 同時指定 API 網址：`https://<帳號>.github.io/inventory-scan/#key=<API金鑰>&url=<API網址>`

請先對金鑰與 API 網址分別做 URL 編碼。同仁開啟連結後，應用程式會在此瀏覽器儲存設定、移除網址中的片段，並顯示「已設定 API 金鑰」。瀏覽器載入頁面時，網址片段只留在瀏覽器端。

Apps Script 端可擇一設定金鑰。

- 手動設定時，在 Apps Script「專案設定」的「指令碼屬性」新增 `API_KEY` 並填入金鑰。
- 使用雜湊初始化時，將金鑰存入本機的 `secrets/api_key.txt`，依序執行 `node scripts/prepare-deploy.js` 和 `node scripts/make-config.js`。部署目錄 `deploy/` 包含 `Code.gs`、`appsscript.json` 和存放雜湊及管理密碼鹽值的 `Config.gs`，本機的 `.clasp.json` 也放在此處。首次以正確金鑰呼叫 API 時，程式會寫入 `API_KEY` 指令碼屬性。已有該屬性時，以屬性中的金鑰為準。

執行 `node scripts/make-config.js`、`bash scripts/deploy-gas.sh` 或 `bash scripts/smoke-prod.sh` 前，請在環境中設定 `INVENTORY_ADMIN_PASSWORD`。管理密碼的部署設定只保存 SHA-256 雜湊和隨機鹽值。手動部署時，也需將產生的 `deploy/Config.gs` 加入 Apps Script 專案，才能驗證管理密碼。

請勿將 `Config.gs` 或 `secrets/api_key.txt` 提交到版本控制。

## iPhone 使用注意

- 請透過 HTTPS 開啟網站，使用 Safari，或在 iOS 14.3 以上使用 Chrome。
- LINE 或 Facebook 的內建瀏覽器可能擋住鏡頭。請從右上角選單選擇「以 Safari 開啟」。
- 第一次開啟鏡頭時，請點選「允許」以授權相機。
- iOS 不支援網頁震動。手電筒是否可用取決於 iOS 版本和裝置回報的相機功能。
- 可從 Safari 的分享選單選擇「加入主畫面」，以獨立視窗開啟盤點工具。主畫面網頁 App 的相機支援會因 iOS 版本而異，建議在 iOS 16.4 或更新版本實機確認。若無法開啟鏡頭，可回到 Safari 刷讀。

## 掃描槍

使用 USB 或藍牙掃描槍時，請設定為 HID 鍵盤模式，並將掃描後綴設為 Enter。開始盤點後，點一下條碼輸入欄即可刷讀。

舊版「場次」分頁會自動加入「結束時間」與「結束者」。若同一門市原有多個進行中場次，系統會保留最後新增的場次為進行中，並結束該門市其餘場次。仍可依場次查詢所有既有明細。

升級前尚未在雲端建立的舊版場次，可使用「匯出本機備份」保留資料。新盤點從門市選擇畫面開始。

## 自動部署腳本（box 上）
1. `clasp login`（buyer@ehobby.com.tw）。
2. `bash scripts/deploy-gas.sh`：第一次會建立新試算表「條碼盤點紀錄」與綁定的 Apps Script，推送 Code.gs／appsscript.json／Config.gs（包含 API 金鑰雜湊、管理密碼雜湊及鹽值），建立網頁應用程式部署；之後再執行會更新同一個部署（網址不變）。網址等資訊寫在 `secrets/deploy_info.json`。
3. 第一次部署後，用 buyer 帳號開啟 Apps Script 編輯器，執行 `setup` 並同意授權（試算表權限）。
4. `bash scripts/smoke-prod.sh`：用「測試門市」實測 ping、錯誤金鑰、建立／加入場次、上傳、重送不重複、彙總、結束場次、結束後拒絕寫入。測試只會使用新建的「測試門市」場次，並在結束前將測試明細標成已刪除。
